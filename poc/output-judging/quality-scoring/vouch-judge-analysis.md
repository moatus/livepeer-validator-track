# Can Vouch's judge scores help identify generator models?

Local research, 25 October 2026. **Recommendation: yes to a small controlled test of score profiles as an additional signal; no to treating Vouch's final score as an existing model identifier.** The useful hypothesis is that generators have reproducible patterns of strengths and failures across fixed probes. A judge could compress those patterns into a measurable feature vector. Quality differences can carry identity information without quality and identity being the same thing. Success would mean useful additional detection power under stated conditions, not proof of hidden weights.

The fixture is a sign-reading example, not a receipt for every seeded judgment. Provider fields also reference `fal.usage.tokens`.

The [provider's API documentation](https://fal.ai/models/nvidia/nemotron-3-nano-omni/vision/api) describes a general image-plus-text reasoning endpoint, with 30B total/3B active parameters. It documents defaults of temperature 0.7, top-p 0.95, no-think mode and 1,024 output tokens. **Those are current provider defaults, not verified effective historical Livepeer settings.** Neither the source nor describe response pins a weights hash, checkpoint revision, quantization, inference implementation or immutable deployment version. Certainty: high for capability-to-provider endpoint mapping; insufficient for exact serving checkpoint/configuration or every past call. Searching local workflow-kit, discovery-service and gateway SDK/client resources did not resolve that missing detail.

This is a general VLM prompted to judge art, not a dedicated reward model trained and validated for generator attribution. A trained reward model might offer more stable or discriminative features; it might also discard provenance-relevant detail. Either kind needs the same attribution experiment. Access to the judge's internal activations would describe how **the judge processes an input**, not directly expose the generator's internals or execution provenance.

**The two passes are separate requests, not independent evidence sources.** They run concurrently with identical image, prompt, capability and session ID. Neither sees the other response in application code. No temperature, top-p, seed, judge diversification or server-side independence control is supplied. Provider randomness, caching, scheduling or shared serving state are unobserved. Each pass can retry once with an extra JSON-only instruction after parsing failure. Failures and selective retries complicate variance estimates; the final `passes` field counts usable votes, not all attempts. [Client request construction, lines 121–135](https://github.com/martinvibes/vouch-studio/blob/f400251dcee98eb3add551499af63b83a9323613/src/livepeer/client.ts#L121-L135) confirms no hidden application sampling settings.

Video is reduced to three side-by-side frames at 15%, 50%, 85%, each scaled to width 512 and JPEG encoded; missing duration falls back to five seconds. This can judge sampled appearance/consistency but misses most motion, intervening failures and audio. It is not a full-video identity signal. ## What the committed seed data establish

The [benchmark script, lines 22–98](https://github.com/martinvibes/vouch-studio/blob/f400251dcee98eb3add551499af63b83a9323613/scripts/benchmark.ts#L22-L98) describes real Livepeer runs, rotating three contenders per brief and mirroring/downscaling media afterward. The committed JSON contains 14 first-round shootouts: ten image and four video; 42 entries, 41 graded and one failed render. Each image model has three different briefs; each video model has two, except one has only one graded output. There are no same-prompt/model generation replicates. Thirty-five graded entries retain two passes, six retain one. No human picks are recorded. Creation timestamps fall on 23 September 2026. Extracted rows: [seed-summary.json](seed-summary.json).

A bounded observation already illustrates information loss: `flux-pro` and `grok-imagine-quality` both receive total 86.1 on different image briefs. Many generators share craft=9/aesthetics=9. A single model, `flux-schnell`, spans totals 82.4–96.6 across its three different prompts. This demonstrates collisions and prompt-associated variation; it does **not** estimate within-prompt generator variance, discrimination accuracy or causal model effects. Different prompt assignments, only one output per pairing, provider-specific defaults, missing pass records and price/time components prevent controlled attribution. The retained JSON also does not prove which historical prompt/backend revision produced each judgment; current source is not a historical execution receipt. Seed means could prioritize pilot questions, but training/test splitting these 41 records would produce misleading confidence.

## When a profile could work, and where it can fail

A scalar discards the distinction between, for example, good typography/weak anatomy and weak typography/good anatomy. A fixed-probe vector could preserve that pattern and classify an enrolled model family or flag departure from a reference distribution. Aggregate several independently generated outputs per probe: the observable is a **distribution over generator outputs plus judge variation**, not one signature number. Measure whether between-model separation exceeds these sources of within-model variation.

Absolute rubric scores support reusable reference profiles but suffer calibration/style bias. Direct pairwise judgments may discriminate close outputs better, yet depend on the comparison set and presentation order; randomize A/B order and measure reversals if added. Vouch currently implements only absolute grading followed by rank. Rank itself loses margins and changes when contenders change.

Content sensitivity, fashionable-style preferences and judge familiarity may carry useful signal while failing under new prompt categories, close checkpoints, fine-tuning, changed samplers, image compression or postprocessing. Hold the judge and rubric fixed; version changes require recalibration. Include unknown-generator rejection: forcing every output into a known label guarantees confident mistakes on new models. A model can match another model's scalar quality without matching its vector, but an adaptive operator could reroll, edit, select or optimize outputs to match the vector too. Test that separately from ordinary honest variation.

The brief and requirement text are interpolated into the judging prompt; visible image text is also untrusted input. Prompt injection can target both checklist construction and grading. Blindness to an explicit model name reduces label bias but does not eliminate identifying watermarks, image style, or other incidental clues. Judge scores supplied by an operator can simply be fabricated: any useful audit needs independently obtained scores bound to the exact output bytes, prompt and judge configuration. A validator receiving only scores sees less content, but the remote judge still receives the brief/checklist and output image/contact sheet; this is not content-private validation.

[KBF](https://arxiv.org/html/2605.29524v3) and [IRIS](https://arxiv.org/html/2607.20860v1) provide relevant examples of calibrated behavioral audits, using factual-boundary responses and visible random-string features respectively. Their language-model probe results do not validate image/video attribution. A VLM judge could be complementary, but may discard precisely the low-level information a simpler output-feature classifier preserves. The earlier ASR 36/36 and SD 80/80 runtime-hook results do not transfer to closed APIs, where those generator internals are unavailable.

## Minimal experiment to decide whether this is worth pursuing

This is a test specification, not an implementation proposal or authorization for paid runs.

1. **Small matched collection:** start with four image generators, including a closely related pair. Use 24 prompts spanning several visual skills and four independent generation draws per prompt/model: 384 images. Keep common settings matched where feasible; record native settings, exact provider model/version, seeds when available, and output hashes. Treat hidden provider defaults as limitations. Reserve a fifth generator for unknown-model tests. Fix the judge version/configuration, preprocessing, rubric and checklist for each prompt before scoring; do not let checklist randomness vary across generators.
2. **Separate judge noise:** repeat-score 32 byte-identical outputs three times each, retaining every raw pass, settings, attempt, parse failure and parsed vote. Quantify check disagreement and score variance before averaging. Stable scores are necessary but do not establish attribution. Low-temperature scoring is worth testing, with settings explicitly controlled rather than assumed.
3. **Leakage-free split:** assign whole prompts (including paraphrases) to training/calibration/test, for example 12/6/6, before feature selection. All outputs, generator seeds and judge repeats from a prompt stay in its split. Use disjoint generation seeds across splits; do not reuse images or near-duplicate renders. Select probes/features on training only; set rejection/alarm thresholds on calibration; open the held-out test once. Small pilot intervals will be wide.
4. **Matched comparisons:** compare (a) final Vouch total and rank, (b) quality scalar alone, (c) numeric/categorical vector of per-skill checks, craft and aesthetics, and (d) simple output features such as dimensions, colour/edge statistics and a fixed image embedding. Strip file names, model labels, URLs, price and latency from behavioral features. Keep price/time as a separately labeled operational baseline. Add vector to the simple-feature baseline to measure incremental information; use a small regularized classifier or reference-distance detector rather than a large learned system. For a text-model arm, compare judge features against KBF/IRIS under the same models and query/cost budget; do not apply KBF directly to generated images or Vouch's image judge and call that generator verification.
5. **Decision criterion:** report held-out confusion, calibration, unknown rejection, false alarms under honest changes, and substitution detection at a preselected false-positive rate, with prompt-clustered uncertainty. Compare samples and cost needed for the same detection target. Report within-model versus between-model distances. Then test modest JPEG/resizing changes, related checkpoints and selection of the best-matching output from several draws. Add a few content-injection probes. Require improvement over simpler features or KBF/IRIS where applicable, not an attractive headline accuracy or training-set separation.

**Practical next step:** preserve Vouch's unmerged judge observations and run this bounded pilot only if source-level configuration and independent scoring can be controlled. If the vector supplies stable additional held-out signal, use it as probabilistic supporting evidence or a trigger for further checks. If it mostly measures prompt difficulty, style preference or prices, keep its quality-ranking use and drop the identity claim.
